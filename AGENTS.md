# Hex Colony — Project Agent Rules

2D-игра на Unity, стадия после MVP. Этот файл содержит только факты проекта и оверрайды.
Универсальные правила лежат в общем пакете и не дублируются здесь.

## Порядок чтения

1. `.agents/global-agent-rules/AGENTS.md` — универсальный workflow и Unity-политика.
2. `.agents/global-agent-rules/code-style.md` — стиль C#.
3. Этот файл — факты проекта и оверрайды.
4. `docs/MVP_hex_colony.md` — **канонический дизайн-контракт текущего этапа**.
5. `docs/DEVELOPMENT_PLAN.md` — стадии и чеклист.

В пакете `.agents/global-agent-rules/` лежат **только** эти два файла. Каталогов
`pipelines/`, `templates/`, `skills/` в проекте нет, и они не планируются.
Ссылки на них внутри общего `AGENTS.md` считать несуществующими: ничего не искать,
не восстанавливать и не спрашивать о них. Замещающие правила — в разделе «Оверрайды» ниже.

`docs/GDD_hex_colony.md` — справочный документ с материалом за пределами MVP.
Он **не** является контрактом и не служит поводом реализовывать что-либо сверх спеки.

## Приоритет правил

Явная инструкция человека → этот файл → общий `AGENTS.md` → `code-style.md` → дефолты инструмента.

## Факты проекта

- Движок: Unity 6, 2D. Render pipeline и input stack — как в существующем проекте, не менять.
- Стадия: после MVP. Игровой цикл замкнут, стадии M6–M10 закрыты, идёт M11 из `docs/DEVELOPMENT_PLAN.md`.
  Ограничения прототипа сняты решением человека 29.08.2026 — конкретно какие, сказано ниже по тексту.
  Отговорка «это же прототип» больше не работает. Архитектура «на будущее» при этом по-прежнему
  не нужна: простое рабочее решение остаётся предпочтительным, пока оно не мешает следующей стадии.
- Арт по умолчанию строится кодом: процедурные меши (гекс, дороги, декор биомов, модельки
  месторождений), цвета через `MaterialPropertyBlock`, анимации на корутинах. Список того, что уже
  есть, — в `docs/MVP_hex_colony.md`.
- Запрет на спрайты, текстуры и шейдеры снят решением человека 29.08.2026. Снят как разрешение, а не
  как рекомендация: ассет или шейдер заводится, только когда процедурное решение упирается в потолок,
  и в отчёте пишется, во что именно оно упёрлось. Заранее «на всякий случай» — нет. Первый ожидаемый
  повод — запекание плитки в один меш с цветом в вершинах, если замер FPS в M8 покажет просадку.
- Бинарные ассеты перечисляются здесь поимённо, каждый с лицензией рядом с файлом. Не перечисленный
  ассет считается мусором и удаляется. На 29.08.2026 он один:
  - шрифт `Assets/_Project/Resources/Inter-Regular.ttf` (OFL, поставляется с редактором Unity,
    лицензия лежит рядом). Он обязателен: встроенный `LegacyRuntime.ttf` опирается на системный
    Arial, а в веб-сборке системных шрифтов нет — кириллица там не рисуется вовсе, и в редакторе
    этого не видно. Не удалять и не заменять на встроенный.
- Транспорт автоматизации: официальный Unity CLI.
- Ветки: рабочая ветка одна — `main`. Фичевые, стадийные и экспериментальные ветки не заводить,
  коммитить стадию прямо в `main`. Единственная вторая ветка — `gh-pages`, и в ней лежит только
  собранная веб-сборка: она публикуется отдельным репозиторием из `Build/Pages` одним коммитом
  с `--force` и с историей `main` не пересекается.
- Сборки: только `Game.Runtime` и `Game.Tests.EditMode`.
- Структура папок — раздел 5 спеки MVP.

## Оверрайды к общим правилам

- **Unity CLI.** Общий `AGENTS.md` ссылается на `pipelines/unity-cli.md` — файла нет. Используем официальный Unity CLI напрямую, по документации Unity. Отдельного пайплайн-документа в проекте не заводить.
- **Тесты и сборки.** Общий `AGENTS.md` ссылается на `pipelines/unity-testing-asmdefs.md` — файла нет. Действует правило этого файла: сборки только `Game.Runtime` и `Game.Tests.EditMode`, EditMode-тесты по списку из раздела 5 спеки, PlayMode-тесты не пишем — решение человека, стадия на это не влияет. Если проверка требует Play Mode — она ручная и отмечается в отчёте.
- **Bootstrap-процедура.** README пакета и шаблоны `templates/` отсутствуют. Проект уже развёрнут, повторный bootstrap не требуется.
- **Конфиг.** `GameConfig` (ScriptableObject) содержит только числа баланса, перечисленные в разделе 5 спеки. Цвета, границы и скорость камеры, размеры UI остаются локальными `[SerializeField]`. Не выносить в конфиг значение только потому, что оно числовое.
- **Именование.** Классов `Manager`, `Controller`, `Service`, `Helper` в проекте нет. Имена систем зафиксированы в разделе 5 спеки; при добавлении новых называть по ответственности.
- **События.** Обычные C#-события на самих системах. Event bus, DI-контейнер, service locator, синглтоны, пулы объектов и интерфейсы «на будущее» не добавлять.
- **Git-flow.** Общие правила про ветку под задачу и pull request не применяются: репозиторий одного
  исполнителя, ревью по PR нет. Работаем и коммитим в `main` напрямую, ветку под стадию не создаём.
- **Документация.** Плановые изменения пишутся в `docs/DEVELOPMENT_PLAN.md`. Отдельные QA-файлы, логи задач и архитектурные документы под каждую правку не создавать.
- **Workstreams и cross-agent handoff.** Не применяются: один исполнитель, один поток работы. Достаточно обновлять `DEVELOPMENT_PLAN.md`.
- **UI Toolkit pipeline.** В проекте отсутствует и в MVP не применяется. HUD — минимальный текст.
- **Персистентность.** Сохранения партии нет и в план оно не заведено: закрыл вкладку — начал заново.
  Разрешено ровно одно исключение решением человека — лучший счёт между запусками в `PlayerPrefs`
  (стадия M10). Прохождение обучения по-прежнему не сохраняется. Всё остальное про сейв — вне скоупа,
  бэклог не заводить.

## Известные и принятые ограничения

Перечисленное ниже — решения человека, а не дефекты. Не «чинить», не предлагать исправление, не расширять спеку ради их устранения:

- возможен soft lock при исчерпании ресурсов. Препятствия из M9 делают его вероятнее — это тоже
  принято. Если плейтест покажет, что партия рвётся регулярно, предохранитель один: стартовый
  щебень, а не новая механика;
- переполнение склада уничтожает ресурс безвозвратно. С M10 потеря вдобавок бьёт по финальному счёту;
- дороги нельзя снести. На этом стоит липкий родитель дороги из M7: раз маршрут не может исчезнуть,
  найденный однажды путь остаётся валидным навсегда.

Снято решением человека 29.08.2026: строка «условия победы нет» больше не действует — конец партии
и финальный счёт делаются в стадии M10, детали в `DEVELOPMENT_PLAN.md`.

## Definition of Done

Формат финального отчёта — из общего `AGENTS.md` (`## Done / ## Verification / ## Project Setup / ## Risks`).
Проверки, которые не удалось выполнить, помечать `degraded` с точной причиной.
Не выдавать скриншот за доказательство интерактивного поведения.
