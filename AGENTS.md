# Hex Colony — Project Agent Rules

Прототип 2D-игры на Unity. Этот файл содержит только факты проекта и оверрайды.
Универсальные правила лежат в общем пакете и не дублируются здесь.

## Порядок чтения

1. `.agents/global-agent-rules/AGENTS.md` — универсальный workflow и Unity-политика.
2. `.agents/global-agent-rules/code-style.md` — стиль C#.
3. Этот файл — факты проекта и оверрайды.
4. `docs/MVP_hex_colony.md` — **канонический дизайн-контракт текущего этапа**.
5. `docs/DEVELOPMENT_PLAN.md` — стадии и чеклист.

В пакете `.agents/global-agent-rules/` лежат **только** эти два файла. Каталогов
`pipelines/`, `templates/`, `skills/` в проекте нет, и они не планируются.
Ссылки на них внутри общего `AGENTS.md` считать несуществующими: ничего не искать,
не восстанавливать и не спрашивать о них. Замещающие правила — в разделе «Оверрайды» ниже.

`docs/GDD_hex_colony.md` — справочный документ с материалом за пределами MVP.
Он **не** является контрактом и не служит поводом реализовывать что-либо сверх спеки.

## Приоритет правил

Явная инструкция человека → этот файл → общий `AGENTS.md` → `code-style.md` → дефолты инструмента.

## Факты проекта

- Движок: Unity 6, 2D. Render pipeline и input stack — как в существующем проекте, не менять.
- Стадия: прототип. Замкнуть игровой цикл, а не построить архитектуру на будущее.
- Арт отсутствует: спрайтов, текстур и шейдеров в проекте нет и не предлагать. Разрешено то, что строится кодом:
  процедурные меши (гекс, декор биомов), цвета через `MaterialPropertyBlock` и анимации на корутинах.
  Список того, что уже есть, — в `docs/MVP_hex_colony.md`.
- Единственный бинарный ассет — шрифт `Assets/_Project/Resources/Inter-Regular.ttf` (OFL, поставляется
  с редактором Unity, лицензия лежит рядом). Он обязателен: встроенный `LegacyRuntime.ttf` опирается
  на системный Arial, а в веб-сборке системных шрифтов нет — кириллица там не рисуется вовсе, и в
  редакторе этого не видно. Не удалять и не заменять на встроенный.
- Транспорт автоматизации: официальный Unity CLI.
- Сборки: только `Game.Runtime` и `Game.Tests.EditMode`.
- Структура папок — раздел 5 спеки MVP.

## Оверрайды к общим правилам

- **Unity CLI.** Общий `AGENTS.md` ссылается на `pipelines/unity-cli.md` — файла нет. Используем официальный Unity CLI напрямую, по документации Unity. Отдельного пайплайн-документа в проекте не заводить.
- **Тесты и сборки.** Общий `AGENTS.md` ссылается на `pipelines/unity-testing-asmdefs.md` — файла нет. Действует правило этого файла: сборки только `Game.Runtime` и `Game.Tests.EditMode`, EditMode-тесты по списку из раздела 5 спеки, PlayMode-тесты в MVP не пишем. Если проверка требует Play Mode — она ручная и отмечается в отчёте.
- **Bootstrap-процедура.** README пакета и шаблоны `templates/` отсутствуют. Проект уже развёрнут, повторный bootstrap не требуется.
- **Конфиг.** `GameConfig` (ScriptableObject) содержит только числа баланса, перечисленные в разделе 5 спеки. Цвета, границы и скорость камеры, размеры UI остаются локальными `[SerializeField]`. Не выносить в конфиг значение только потому, что оно числовое.
- **Именование.** Классов `Manager`, `Controller`, `Service`, `Helper` в проекте нет. Имена систем зафиксированы в разделе 5 спеки; при добавлении новых называть по ответственности.
- **События.** Обычные C#-события на самих системах. Event bus, DI-контейнер, service locator, синглтоны, пулы объектов и интерфейсы «на будущее» не добавлять.
- **Документация.** Плановые изменения пишутся в `docs/DEVELOPMENT_PLAN.md`. Отдельные QA-файлы, логи задач и архитектурные документы под каждую правку не создавать.
- **Workstreams и cross-agent handoff.** Не применяются: один исполнитель, один поток работы. Достаточно обновлять `DEVELOPMENT_PLAN.md`.
- **UI Toolkit pipeline.** В проекте отсутствует и в MVP не применяется. HUD — минимальный текст.
- **Персистентность.** Сохранение вне скоупа. Требования к сейву не реализовывать и не заводить бэклог — стадия прототипа.

## Известные и принятые ограничения

Перечисленное ниже — решения человека, а не дефекты. Не «чинить», не предлагать исправление, не расширять спеку ради их устранения:

- возможен soft lock при исчерпании ресурсов;
- переполнение склада уничтожает ресурс безвозвратно;
- дороги нельзя снести;
- условия победы нет.

## Definition of Done

Формат финального отчёта — из общего `AGENTS.md` (`## Done / ## Verification / ## Project Setup / ## Risks`).
Проверки, которые не удалось выполнить, помечать `degraded` с точной причиной.
Не выдавать скриншот за доказательство интерактивного поведения.
