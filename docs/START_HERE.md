# Старт разработки

Этот файл нужен только для развёртывания. В репозиторий его класть не обязательно.

## 1. Раскладка файлов

```
<корень проекта Unity>/
  AGENTS.md                         ← из этой поставки
  CLAUDE.md                         ← из этой поставки
  gamedesign/
    MVP_hex_colony.md               ← канонический контракт
    DEVELOPMENT_PLAN.md             ← чеклист стадий
    GDD_hex_colony.md               ← справочно
  .agents/
    global-agent-rules/
      AGENTS.md                     ← из пакета с вебинара
      code-style.md                 ← из пакета с вебинара
```

В `.agents/global-agent-rules/` кладём **только эти два файла**.

Не кладём:
- `README.md` пакета — это инструкция по bootstrap из полного репозитория, которого нет. Проект уже развёрнут, а файл будет отправлять агента искать несуществующие каталоги.
- `unity-ui-toolkit-interface-pipeline.md` — в MVP не применяется, плюс содержит требования чужого проекта (Minecraftorio: стрелки прогресса, огонь печи, слоты верстака). Они начнут просачиваться в наш UI.

## 2. Две правки в файле пакета

В `.agents/global-agent-rules/AGENTS.md` удалить два висячих упоминания:

- в разделе **Unity Rules** — фразу `Follow pipelines/unity-cli.md.`
- в разделе **Unity Testing Policy** — строку `Follow pipelines/unity-testing-asmdefs.md.`

Обе ссылки ведут в отсутствующие файлы. Замещающие правила уже прописаны в корневом `AGENTS.md`,
и он же явно объявляет каталоги `pipelines/`, `templates/`, `skills/` несуществующими — так что
даже если правку забыть, агент не пойдёт их искать.

Остальной текст пакета не трогаем: если позже получишь полную папку, лишние ручные изменения
будут мешать её обновить.

## 3. Первый промпт

```text
Прочитай AGENTS.md в корне и всё, на что он ссылается, в указанном порядке.
Затем осмотри проект: версия Unity, пакеты, существующие папки и сборки, git status.

После этого не пиши код. Дай Feature Readiness по стадии M1 из
gamedesign/DEVELOPMENT_PLAN.md и список вопросов одной пачкой, если уверенность ниже 90%.
```

## 4. Промпт на каждую следующую стадию

```text
Стадия <M2> из gamedesign/DEVELOPMENT_PLAN.md. Реализуй только её,
механики следующих стадий не трогай.

Перед началом — Feature Readiness. После — отчёт в формате Definition of Done
и обновление чеклиста стадии в DEVELOPMENT_PLAN.md.
```

## 5. Что проверять руками

Критерий «Готово когда» в конце каждой стадии плана. Агент не может доказать
интерактивное поведение — Play Mode проходишь сам.
