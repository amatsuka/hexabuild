# MVP Spec — Hex Colony

> **Канонический документ MVP.** При расхождении с `GDD_hex_colony.md` побеждает этот файл.
> Все числа проставлены как стартовые значения для тюнинга. Открытых вопросов нет.
> **Цель:** замкнутый игровой цикл на примитивах, играбельный в Play Mode.

---

## 1. Что делаем

2D-игра видом сверху на гексагональном поле. Реальное время, казуальный темп, без арта — одноцветные шейпы.

**Цикл:** очки → открыть плитку → построить дорогу → ресурсы едут на склад → merge на складе → материалы + очки → повтор.

**Осознанные упрощения MVP** (решено человеком, не переделывать и не «чинить»):
- Возможен soft lock, если игрок исчерпает ресурсы. Допустимо для прототипа.
- Нет условия победы — песочница.
- Нет сохранения, главного меню, звука, анимаций, туториала, сноса дорог.
- UI минимальный, без дизайн-системы и UI Toolkit pipeline.

## 2. Поле

| Параметр | Значение | Где живёт |
|---|---|---|
| Ориентация гексов | pointy-top | константа |
| Координаты | axial (q, r) | — |
| Радиус поля | 6 (127 плиток) | `GameConfig` |
| Рендер | префаб гекса, инстанцируется скриптом (не Tilemap) | — |
| Ширина гекса | 1 unit | константа |
| Seed генерации | задаётся в конфиге, 0 = случайный | `GameConfig` |

### 2.1 Состав карты

Центр (0,0) — Метрополия. Остальные 126 плиток генерируются случайно:

| Содержимое плитки | Вероятность |
|---|---|
| Пусто (транзит) | 30% |
| 1 месторождение | 45% |
| 2 разных месторождения | 20% |
| 3 разных месторождения | 5% |

Тип каждого месторождения выбирается равновероятно из трёх (дерево, камень, руда), без повторов внутри плитки. Запас месторождения — случайное целое **8–20**.

**Гарантия генератора:** минимум одна из шести плиток вокруг Метрополии содержит камень. Иначе партия не стартует экономически.

### 2.2 Состояния плитки

| Состояние | Отображение |
|---|---|
| Скрытая | тёмно-серый гекс |
| Доступная (смежна с открытой) | светло-серый гекс |
| Открытая | бежевый гекс + 1–3 цветные точки по числу месторождений |
| Истощённая | тот же вид, альфа 0.35 |
| С дорогой | белая линия поверх гекса |
| Метрополия | синий гекс |

Точка месторождения гаснет (альфа 0.35) при исчерпании этого месторождения. Плитка становится `Depleted`, когда исчерпаны **все** её месторождения; она остаётся проходимой для дорог.

Цвета: дерево зелёный, камень серый, руда охра, доска светло-зелёный, щебень светло-серый, слиток светло-оранжевый. Конкретные значения — `[SerializeField]` на префабах, не в `GameConfig`.

## 3. Правила

### 3.1 Открытие плитки
- Только смежная минимум с одной открытой.
- Стоимость **20 очков**, фиксированная.
- До открытия содержимое неизвестно.
- Ограничений по количеству и частоте открытий нет.

### 3.2 Дороги
- Строятся на открытой плитке, стоимость **1 щебень**.
- Плитка производит, только если есть непрерывная цепочка дорог до Метрополии.
- Плитка, смежная с Метрополией, подключается одной дорогой на себе.
- Связность: BFS от Метрополии по плиткам с дорогами. Пересчёт по событию постройки, не в `Update`.

### 3.3 Добыча
- **Один таймер на плитку**, независимо от числа месторождений: **1 единица раз в 3 секунды**.
- Месторождения отдают ресурс по кругу (round-robin), пропуская исчерпанные. Плитка с деревом и камнем выдаёт: дерево → камень → дерево → камень.
- Каждая выдача списывает 1 из запаса соответствующего месторождения.
- Таймер останавливается, когда все месторождения исчерпаны.

### 3.4 Доставка
- Время в пути: **1 секунда × длина кратчайшего дорожного пути в плитках**.
- Визуал: кружок цвета ресурса едет вдоль пути, Lerp по точкам, без физики.
- Путь фиксируется в момент отправки и не пересчитывается.

### 3.5 Склад
- Сетка **5×5 = 25 клеток**, панель справа.
- Новый ресурс кладётся в первую свободную клетку: скан слева направо, сверху вниз.
- **Свободных клеток нет → ресурс уничтожается.** Красная вспышка панели, счётчик потерь в HUD. Добыча на плитке при этом продолжается и запас расходуется.

### 3.6 Merge
Клик по ресурсу на складе:
- ресурсов этого типа **≥ 5** → списать 5, выдать 2 крафтовых, **+25 очков**;
- иначе **≥ 3** → списать 3, выдать 1 крафтовый, **+10 очков**;
- иначе — ничего, короткий отказной фидбек.

Смежность клеток не учитывается. Drag&drop в MVP не делаем. Результат кладётся в освободившиеся клетки по правилу 3.5.

### 3.7 Рецепты

| Из | Получается |
|---|---|
| Дерево ×3 | Доска |
| Камень ×3 | Щебень |
| Руда ×3 | Слиток |

Крафтовые ресурсы занимают клетки склада наравне с базовыми и дальше не мержатся. Практическое применение имеет только **щебень** (валюта дорог); доска и слиток нужны ради очков.

### 3.8 Старт партии
Метрополия открыта. **40 очков**, **3 щебня**.

## 4. Управление и UI

- Камера: пан drag, зум колесом, границы по радиусу поля. Параметры камеры — `[SerializeField]` на компоненте камеры, не в `GameConfig`.
- ЛКМ по доступной скрытой плитке → открыть за очки.
- ЛКМ по открытой плитке без дороги → построить дорогу за щебень.
- ЛКМ по ресурсу на складе → merge.
- Нехватка валюты → короткое сообщение в HUD.

**HUD, обычный текст без дизайна:** очки · щебень · доски · слитки · потеряно · заполненность склада `18/25`.

## 5. Архитектура

```
Assets/_Project/
  Scripts/                 Game.Runtime.asmdef
    Core/       GameConfig (ScriptableObject), GameSession, GameState
    Grid/       HexCoord, HexMap, TileData, Deposit, TileView
    Roads/      RoadNetwork
    Economy/    ResourceType, ProductionSystem, DeliverySystem, ResourceMover
    Storage/    StorageGrid, StorageView
    Merge/      MergeRules (ScriptableObject), MergeSystem
    Economy/    Wallet
    UI/         HudView, GameInput
  Tests/
    EditMode/                Game.Tests.EditMode.asmdef
  Prefabs/
  ScriptableObjects/
  Scenes/
```

**Сборки:** только `Game.Runtime` и `Game.Tests.EditMode`. `Game.Editor` и `Game.Tests.PlayMode` не создавать, пока не появится реальная нужда.

**Правила:**
- Правила игры — чистые C#-классы. MonoBehaviour только на View, вводе и точке входа.
- `GameConfig` содержит **только числа баланса**: радиус поля, seed, веса генерации, диапазон запаса, интервал добычи, секунды на плитку доставки, размер склада, стоимость открытия, стоимость дороги, пороги и очки merge, стартовые очки и щебень. Цвета, границы камеры, скорость зума — локальные `[SerializeField]`.
- Связь систем — обычные C#-события на самих системах. Никакого event bus, DI-контейнера, service locator и синглтонов.
- `GameSession` — точка входа: создаёт системы, связывает подписки, владеет `GameState`.

**EditMode-тесты обязательны для:**
- `HexCoord` — соседи, дистанция, конвертация в мировые координаты;
- `RoadNetwork` — связность и её отсутствие, пересчёт после постройки;
- `MergeRules` — пороги 3 и 5, приоритет пятёрки, отказ при недостатке;
- `TileData` — round-robin по месторождениям, пропуск исчерпанных, переход в `Depleted`.

PlayMode-тесты в MVP не пишем.

## 6. Что тюним после первого запуска

Первые кандидаты в `GameConfig`: `storageSize` · `depositReserveRange` · `extractionInterval` · `tileOpenCost` · `mergePoints` · веса генерации месторождений.
